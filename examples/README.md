# queuetruth examples

Runnable Python scripts that use the public Python API (`import queuetruth as qt`) on the synthetic quickstart
dataset. Every script needs the compiled extension `queuetruth._core`: build it with `make develop` in a source
checkout, or install the wheel. Without it the first call raises `QtError` `QT-ENGINE-001`.

All data here is synthetic (generated by `queuetruth-testkit`, no market data). The numbers the scripts print
say nothing about any real venue, instrument or simulator.

## Scripts

| Script | Shows | Extension |
|---|---|---|
| `01_replay_shadows.py` | `qt.sample_shadows`; exact replay with shadows (`qt.replay`): record counters, the 8 book invariants, the shadow outcome block, the data quality verdict; a few rows of `qt.shadow_results` and `qt.shadow_fills` read with `qt.read_table` (pyarrow); `qt.Session` (`advance_to`, `bbo`, `depth`, `queue_ahead`) on one instrument | required |
| `02_zoo.py` | `qt.run_zoo` with every zoo model on the shadows; the leaderboard of `ZooSummary` (`fill_rate_bias` with its 95% CI at each horizon, `brier`, McNemar counts at `h_max`) sorted by absolute bias at 60 s; one model's bias per queue decile from `qt.zoo_errors` | required |
| `03_calibrate_export.py` | `qt.calibrate` (`kind="alloc"`, `family="power3"`, train 2026-06-15, test 2026-06-16): estimate, profile and bootstrap CIs, `held_out` vs `baseline_held_out`, the trust verdict and `beats_default`; then `export` to an hftbacktest snippet. A second fit on a deliberately narrow grid is refused (`QT-CALIB-001`), and is then exported with `force=True` under its NOT VALIDATED header | required |
| `04_score_own_orders.py` | `qt.validate_live` and `score` of the fixture's own-order live log (`own_orders/live`) against the exact arm (with and without self-exclusion) and against a zoo model: `two_by_two`, `bias`, `mcnemar`, the cluster-robust `discordance_clustered` row of `qt.score_tests`, verdict headline | required |
| `05_report.py` | `report`: one HTML file from the outputs of 01 to 04; prints its path and sections | required |
| `06_learned_model.py` | `qt.extract_features`, a comparison zoo run, `qt.fit_hazard` (smaller GBDT than the default), the model card (split, test scores, `zoo_comparison`), `qt.HazardModel.load(...).predict` | required |

`_data.py` holds the shared helpers (dataset lookup, output directories, the shared shadow sample, printing).

Each script is standalone: it samples its own shadows (400 shadows, seed 1) and recomputes what it needs.
`05_report.py` reads the outputs of 01 to 04 from the outputs root and first runs any example whose output is
missing, so it also works on its own.

## Running

From a source checkout (after `make develop`), at the repository root:

```sh
uv run --frozen --no-sync python examples/01_replay_shadows.py
uv run --frozen --no-sync python examples/02_zoo.py
uv run --frozen --no-sync python examples/03_calibrate_export.py
uv run --frozen --no-sync python examples/04_score_own_orders.py
uv run --frozen --no-sync python examples/05_report.py
uv run --frozen --no-sync python examples/06_learned_model.py
```

With a pip install of the wheel (no checkout), write the dataset first and point the examples at it:

```sh
queuetruth fixtures synth --out data
QT_EXAMPLE_DATA=data python examples/01_replay_shadows.py
```

Dataset lookup, in order: env `QT_EXAMPLE_DATA`; `tests/fixtures/synth_small` next to this directory (a checkout);
else `./qt-example-data`, written once with `queuetruth.api.fixtures_synth` (the same generator as
`queuetruth fixtures synth`).

Outputs go to `./qt-examples-out/<script name>/` (relative to the current directory), or to
`$QT_EXAMPLE_OUT/<script name>/` when `QT_EXAMPLE_OUT` is set. A script empties its own output directory before it
runs, but only a directory it wrote before (it carries a `.qt-example` marker file). Nothing is written inside the
dataset or `tests/fixtures`. Delete `qt-examples-out/` (and `qt-example-data/`, if it was written) when done.

## Notes

- `qt.export`, `qt.score` and `qt.report` share their names with the subpackages `queuetruth.export`,
  `queuetruth.score` and `queuetruth.report`. Once a subpackage has been imported (for example by `qt.calibrate` or
  by a first `qt.score` call), the package attribute names the subpackage, not the function. The scripts call
  `qt.api.export`, `qt.api.score` and `qt.api.report`, which are the same functions and always work.
- `04_score_own_orders.py` passes `self_exclude=False`, a keyword extra of `qt.api.score` (not a `ScorecardSpec`
  field), to show the run without self-exclusion.
- For the exact arm with self-exclusion the expected result is zero discordance (`live_only == sim_only == 0`),
  asserted by `python/tests/api/test_api_hybrid.py::test_score_exact_self_excluded_is_concordant` and O-SCORE-4
  (`python/tests/score/test_score_gate.py::test_o_score_4_self_exclusion_real_orders`). The script prints the
  observed counts next to that expectation (on the current build both are 0) and does not assert it.
- The shadows use the default 300 s lifetime, equal to the zoo's default `h_max_ns`. Shadows with a shorter
  lifetime are cancel-bearing for the zoo evaluation: their metrics go to the `cancel_bearing/...` rows of
  `qt.zoo_errors`, and the leaderboard values are null.
