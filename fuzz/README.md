# queuetruth fuzz targets

The service and the CLI accept market-data files from users (SPEC 8.10), so each parser of untrusted bytes has a
cargo-fuzz target here: ITCH 5.0, IEX DEEP+, DBN, the etcsv and Parquet ingest formats, and the crypto capture
formats. The crate is its own Cargo workspace: it needs a nightly toolchain and links libFuzzer, and
`cargo test --workspace` at the repository root never builds it.

| target | what it drives | selector byte (first input byte) |
|---|---|---|
| `itch` | ITCH 5.0 `Reader` (in memory, or a file: raw or gzip behind the decompression guard), `parse`, `encode`, `Mapper` | bits 0-1 price exponent, 2 symbol filter, 3 file, 4 midnight 0 |
| `itch_parse` | ITCH 5.0 framing, `parse` and `encode` only, in memory (no `Mapper`: about 10,000 inputs/s against about 660 for `itch`) | ignored (same layout as `itch`) |
| `iex` | IEX DEEP+ `CaptureReader` (pcap / pcapng; in memory or a raw / gzip file), `FeedReader`, `parse`, `encode`, `Mapper` | bits 0-1 price exponent, 2 symbol filter, 3 file |
| `iex_parse` | IEX DEEP+ capture framing, IEX-TP sequencing, `parse` and `encode` only, in memory | ignored (same layout as `iex`) |
| `dbn` | `DbnReader` (plain or zstd, inferred) by schema (MBO, trades, definitions), `Symbology`, `symbol_map`, `vintage_of` | bits 0-1 price exponent |
| `ingest` | `qt_ingest::ingest` end to end (reader thread, routing, data quality, Parquet writer), then `Dataset::open` and a full read | bits 0-1 format: ITCH, IEX DEEP+, DBN, ITCH with a symbol filter |
| `etcsv` | the etcsv format end to end: `mbo.csv`, then optional `trades.csv` and `instruments.csv` after `\n#--\n` separators; full read back | bits 0 fixed midnight, 1 instruments via the spec, 2 America/New_York, 3 price exponent -4, 4 symbol filter |
| `parquet` | the Parquet format and the dataset reader: the input is a standalone input, the spec's `instruments`, or the MBO part, `instruments.parquet` or source-trades part of an otherwise valid dataset | selector modulo 5: the role |
| `crypto_bitstamp` ... `crypto_tardis` | each `qt_crypto` converter on the input's lines | bits 0-1 exponents, 2 fixed instrument map, higher bits per format (taker window, conf flags, warm-up depth, Kraken depth and checksum precision) |
| `crypto_hyperliquid` | node lines, then an L4 snapshot after the line `#L4SNAPSHOT` | as above, bit 3 block-gap check |
| `crypto_prepare` | `qt_crypto::prepare` on one capture file (input resolution, gzip guard, conversion, session cuts, re-seeding), optionally `qt_crypto::write` and a full read back | bits 0-2 format, 3 America/New_York, 4 strict, 5 write |
| `crypto_json` | `jsonx::parse` and the `units` decimal, date and time parsers; the session day of every parsed timestamp | bits 0-1 exponents |

Every harness checks more than "no panic" (see `src/lib.rs`): an error caused by input bytes is `QT-INPUT-*`,
`QT-CONFIG-*` or `QT-DATA-*`, never `QT-ENGINE-001` or `QT-USAGE-001`; ITCH and DEEP+ messages round-trip through
`encode`; mapped records carry `LAST` and the message sequence; DEEP+ delivers each `(channel, session)` in strictly
increasing sequence order; a dataset that an ingest path wrote opens and reads back; a timestamp's session day
brackets it between two midnights in both session clocks.

## Running

```bash
rustup toolchain install nightly
cargo install cargo-fuzz --locked
cd fuzz
./run.sh 600              # every target, 10 minutes each, at nice 15, -fork=1
./run.sh 60 itch iex      # selected targets
QT_FUZZ_ARGS="-fork=1 -ignore_crashes=1" ./run.sh 600 ingest   # keep going after a crash
```

`run.sh` keeps going when a target finds a crash, prints the targets with findings at the end and exits 1. The
`dbn` and `ingest` targets run with `-malloc_limit_mb=64`, the others with 512. The working corpus goes to
`.scratch/fuzz-corpus/` (git-ignored). `QT_FUZZ_EXTRA=<dir>` adds read-only seeds per target, for example excerpts of
licensed real data that must not be committed. Crashes land in `fuzz/artifacts/<target>/`.

The harnesses write their input files under `$QT_FUZZ_TMP`, by default `<repo>/.scratch/fuzz-tmp` (git-ignored), in
one `qt-fuzz-<pid>-<n>` directory per process and thread. `run.sh` uses its own directory inside `QT_FUZZ_TMP`, clears
it after each target and removes it on exit; `cargo test` removes each test's directory when the test ends.

## Seeds, regressions and known crashes

- `seeds/<target>/` are committed and regenerated byte for byte with `cargo run --example gen_seeds`: synthetic ITCH
  days, DEEP+ captures and DBN files built with the crates' own encoders, the embedded etcsv day
  (`qt_fuzz::ETCSV_MBO`), the Parquet files ingest writes for it, and copies of the crypto test fixtures. No market
  data with redistribution terms is committed.
- `regressions/<target>/` holds every minimized crash input that was fixed. Each one has a regression test next to
  the fix, and `cargo test` here (stable toolchain) replays every seed and regression through its harness.
- `known-crashes/<kind>/` holds findings in code outside this workstream's fixes. The harnesses skip those inputs
  so fuzzing continues past them, and `cargo test` checks that every one still reproduces; once the code is fixed,
  the test fails, the inputs move to `regressions/` and the filter goes.
  - `dbn/`: the `dbn` 0.71.0 decoder panics on a prelude announcing 100 to 103 metadata bytes (plain or zstd).
  - `dbn-alloc/`: a 24-byte DBN file announcing 256 MiB of metadata makes the decoder allocate 256 MiB.
  - `parquet/`: corrupt Parquet metadata panics inside the `arrow-ipc` and `parquet` crates. With
    `QT_FUZZ_KNOWN_DIR=<dir>`, the `parquet` target saves one input per distinct panic site there.

A new finding: `cargo +nightly fuzz tmin <target> <artifact>`, copy the minimized file to `regressions/<target>/`
with a descriptive name, fix the parser, and add a test in the fixed crate that names the file.
